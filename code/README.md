# Reproducible Bologna / Marconi Express experiments

Run with Python 3.12 from this directory:

```bash
pip install -r requirements.txt
python download.py --check
python analyze.py
python verify.py
python revision.py
python verify_revision.py
```

The 32 Excel inputs are already tracked under `../dataset/Aeroporto/` and `../dataset/Marconi Express/`. `download.py --check` verifies their Git blob hashes offline. Without `--check`, it restores only missing files to `../dataset/` from the pinned layout commit in `source_manifest.json`; existing files with a different hash raise an error. `analyze.py` verifies all sources before reading them. The original input commit is retained as provenance in the manifest. The analysis preserves missing ordinary-service observations; only the explicitly labeled sensitivity scenario inserts zeros.

`analyze.py` reproduces the descriptive analysis, fixed chronological experiments, paired day bootstrap, and CSV outputs. The accompanying diagnostic Markdown is generated in Italian; the journal manuscript and publication figures are English. `results/model_metrics.csv` and `results/predictions.csv` contain all model evaluations. Model labels in CSVs are retained from the original analysis for traceability; the paper maps them as follows:

| CSV label | Paper label |
| --- | --- |
| Media storica ora × settimana | MEAN |
| Calendario | CAL |
| Calendario + voli programmati | SCHED |
| Calendario + pax stimati | PAX |
| Ridge calendario + pax stimati | RIDGE |
| Retrospettivo pax e orari effettivi | ACTUAL-EXTRA (archived exploratory model) |

`verify.py` recomputes errors, checks time ordering and sample counts, and reproduces the 1,176 May PAX predictions using `predict.py`. The serialized models are regenerated by `analyze.py` and are not committed. Load joblib objects only from trusted sources.

Example inference (after running the analysis):

```bash
python predict.py --schedule examples/schedule_may.csv --targets examples/targets_may.csv --output examples/predicted_may.csv
```

This is a frozen historical model demonstration. The schedule CSV must contain `SCHEDULED_TIME, FLIGHT_NUMBER, BOUND, ORIDES_CODE` and must be complete from three hours before to four hours after all target hours. The target CSV contains `time, type`, with `type` equal to `DA APT` or `DA FS`. Forecast-time schedule availability and ordinary-service operation must be confirmed separately.

The editorial scripts in this directory generate manuscript figures and tables from these saved CSV results, writing assets to the separate private `paper-airport-express-text/paper/` directory.

You can also invoke each script as `python code/<script>.py` from repository root or by absolute path from another working directory. Paths are resolved by `data_sources.py`; no copy into `code/data/` is needed. Results and model storage remain under `code/results/`.

## Targeted major revision

`revision.py` consumes the original results and verifies/reloads the pinned Excel inputs. It reproduces PAX exactly, then adds matched 24-feature REAL-LOAD, REAL-TIME and REAL-BOTH ablations; a ridge calendar interaction model selected on three expanding pre-test splits; a 28-day daily RECENT baseline with frozen fallback; and a fixed 0.90 quantile model. All four original monthly holdouts are retained. Results are written separately to `results/revision/`.

The protocol is a simulated 00:00 daily batch for 05:00–23:00 that day, with monthly frozen models/load estimates. RECENT alone updates from recorded targets strictly before daily issue. Original scheduled movement selection and cancellation completeness are unverified. None of the tests is prospective schedule-snapshot validation.

`paired_gains.csv` includes PAX–SCHED, calendar/reference gains and ablation gains. `directional_gains.csv` jointly resamples the same days after restricting directions to identical target hours. Other outputs quantify fallback levels, online-history availability, calendar inner-validation choices, peak-error distributions, training-bin calibration and quantile coverage. All bootstrap intervals describe within-month uncertainty and omit between-day serial dependence and multiplicity adjustment.

`verify_revision.py` recomputes metrics, checks matched target timestamps and strictly pre-issue RECENT inputs, confirms calendar validation precedes holdout, and checks quantile coverage/pinball loss. The editorial scripts generate publication figures and LaTeX rows directly from these CSVs in the private text repository. The original diagnostic Markdown remains an archive of the six-model analysis.

Row-level revision artifacts are committed as deterministic gzip-compressed CSVs (predictions.csv.gz, quantile_predictions.csv.gz, recent_audit.csv.gz). The analysis also generates uncompressed local copies, ignored by Git. Readers automatically accept either form through revision_io.py; pandas can read the .csv.gz files directly.

## Journal publication workflow

All editorial Python scripts live in this directory. From this repository's root, run:

```bash
python code/make_paper_figures.py
python code/make_revision_figures.py
python code/make_revision_tables.py
python code/make_journal_tables.py
make -C ../paper-airport-express-text/paper
```

By default the private `paper-airport-express-text` repository is a sibling of this clone. Set `AIRPORT_EXPRESS_TEXT_REPO` to its path for another layout. `verify_paper.py` and `package_submission.py` also operate on that private repository, but require currently missing journal assets documented in its README. The experimental CSVs and original 32 Excel workbooks remain here, unchanged; reproducing the experiments requires no private files.
